# Политика безопасности PaprekolyX

Проект личный, опубликован как витрина. Ниже — правила, которые уже действуют,
и порядок действий при инциденте.

## Какие данные хранятся

| Данные | Где | Доступ |
|---|---|---|
| Товары, категории, тексты сайта | Supabase, публичные таблицы | чтение всем, запись только владельцу |
| Заказы: имя, телефон, e-mail, профиль ВК | Supabase, таблица `orders` | чтение закрыто для посетителей, запись только через серверную функцию |
| Промокоды | Supabase, таблица `promo_codes` | чтение закрыто полностью |
| Выбор темы и состав корзины | `localStorage` браузера посетителя | только у самого посетителя |

Персональные данные используются исключительно для исполнения заказа
и никуда не передаются.

## Что лежит в репозитории и почему это безопасно

**Публичный ключ Supabase** (`sb_publishable_…`) находится в `index.html` открыто.
Это штатный режим: сам по себе ключ ничего не разрешает, доступ ограничивает
Row Level Security на стороне базы.

**Секретный ключ** (`sb_secret_…` или `service_role`) в репозитории
отсутствует и не должен появляться. Он обходит все политики RLS.

## Действующие меры защиты

- **RLS включён на всех таблицах.** Чтение — только каталог, справочники,
  тексты сайта и опубликованные отзывы.
- **Заказ создаётся серверной функцией `create_order()`.** Цены берутся
  из таблицы `products`, а не из запроса браузера, поэтому подменить
  стоимость через консоль нельзя.
- **Прямой `INSERT` в `orders` и `order_items` для анонимных посетителей закрыт.**
- **Отзывы** создаются только неопубликованными, с рейтингом 1–5;
  опубликовать в обход модерации нельзя.
- **Ограничение частоты:** не более 3 заказов за 10 минут с одного
  телефона, профиля ВК или e-mail.
- **Экранирование вывода:** все тексты из базы и введённые пользователем
  экранируются перед вставкой в разметку (защита от XSS).
- **Блокировка повторной отправки** формы на время запроса.

## Если секрет всё-таки попал в репозиторий

Удаление файла из последней версии **не помогает**: секрет остаётся в истории коммитов.

1. Немедленно отзовите ключ: Supabase → Project Settings → API Keys.
2. Выпустите новый ключ.
3. Замените его в `index.html` и загрузите файл заново.
4. Проверьте раздел **Authentication → Logs** и **Database → Logs**
   на предмет подозрительных запросов за период, пока ключ был раскрыт.

## Проверки

Изменения в базе и в интерфейсе проверяются автоматическими тестами
(папка `tests/` рабочей копии): SQL-скрипты прогоняются на реальном
движке PostgreSQL, интерфейс — в jsdom. Среди проверяемого — попытки
подменить цену, читать чужие заказы и публиковать отзывы в обход модерации.
